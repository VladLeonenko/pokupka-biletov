# Снайпер «Кабала святош» — боевой план и разбор сценариев

## Цель
Забронировать ~60 билетов (30 пар по 2 соседних места) на сессии:
- `135037141` — 20 ноября (В ПРОДАЖЕ С 15 СЕНТЯБРЯ)
- `135088882` — 21 ноября (В ПРОДАЖЕ С 15 СЕНТЯБРЯ)

Продажи открываются завтра. Билеты раскупают за пару минут. Оператор может быть не у компьютера → всё автономно.

## Как это устроено (поток)

```
sniper-monitor.mjs
 ├─ resolveEventSessions(url)      → sessionId всех сессий + appKey (1 раз, headless-браузер)
 ├─ цикл: getSessionAvailability() → поллинг каждые --interval мс
 ├─ когда availableCount > 0       → bookSeatsViaApi()  (авто-повтор при гонке)
 ├─ saveResults()                  → data/sniper-results.json
 ├─ notifyEmail()                  → письмо со всеми ссылками на оплату
 └─ GET /api/snipe/results          → админка показывает историю
```

## Сценарии отказов и как их обрабатывает код

| # | Сценарий | Обработка |
|---|----------|-----------|
| 1 | Продажи ещё закрыты (hall возвращает «нет мест») | `getSessionAvailability` ловит ошибку → `availableCount: 0`, монитор продолжает поллить |
| 2 | Продажи открылись | `availableCount > 0` → сразу бронь |
| 3 | **Гонка: конкурент выхватил место** | `bookSeatsViaApi` авто-повтор: покупатель получает следующее лучшее место (до `--max-tries 3` раз) |
| 4 | **Не хватает мест (30% зала онлайн)** | цикл останавливается, когда свободных пар нет. Заказано сколько успели + список `errors` для остальных |
| 5 | Email покупателя невалиден | ошибка на `POST /payments` → покупатель повторяется, после 3 попыток попадает в `errors` (и в письмо) |
| 6 | Афиша сменила API/эндпоинты | ошибки ловятся, пишутся в лог и письмо. Бронь не пройдёт — но данные (контакты, сессии) целы |
| 7 | MXAT сменил sessionId | резолвер перечитывает sessionId из страницы при каждом старте (`--url`). Если жёстко задан и изменился — ошибка в логе |
| 8 | Сеть/таймаут | `getHallJson().catch()` → пауза 800мс → ретрай; монитор не падает |
| 9 | Частичная бронь (часть прошла, часть нет) | `{results, errors}` — успешные сохранены (ссылки), неудачные в errors |
| 10 | Rate limit (429) | параллелизм 5, при 100% фейле пауза 1200мс |
| 11 | Ссылки на оплату протухают (холд ~45 мин) | `remainingTime` в результате; письмо уходит сразу — успеть оплатить за 45 мин |
| 12 | Пушкинская карта / спец-тарифы | для «Кабалы» не требуется (обычные места) |

## Ключевой факт: «только 30% зала онлайн»

- Зал МХТ ~868 мест. Онлайн продаётся ~30% ≈ 260 мест.
- 60 билетов = 30 пар ≈ 23% онлайн-инвентаря. Реально, но нужно успеть за 2–3 минуты.
- **Риск**: лучшие пары (партер) могут быть не в онлайн-выкладке. Если 30% — это только часть партера/бельэтажа, бот возьмёт лучшие из того, что выложено.

## Стратегия на гонку

1. **Держать монитор запущенным заранее** (за ~10–15 мин до старта), интервал `--interval 1000` (1 сек).
2. Бронь параллельно (`--concurrency 5`), авто-повтор (`--max-tries 3`).
3. Ссылки уходят на почту + сохраняются в `data/sniper-results.json` + видны в админке.
4. Оплата вручную (или через СБП-ссылку) в течение ~45 мин.

## Запуск (боевой)

```bash
cd backend

# вариант А — по URL (сам резолвит сессии, включая завтрашние):
npm run sniper:monitor -- \
  --url https://mxat.ru/repertuar/show/kabala_svyatosh/ \
  --contacts-file sniper-contacts.json \
  --notify-email vladleo2020@gmail.com \
  --interval 1000 --concurrency 5 --max-tries 3

# вариант Б — напрямую по целевым сессиям (быстрее, без браузера):
npm run sniper:monitor -- \
  --session 135037141 --session 135088882 \
  --contacts-file sniper-contacts.json \
  --notify-email vladleo2020@gmail.com \
  --interval 1000 --concurrency 5
```

## Контакты покупателей (`sniper-contacts.json`)

```json
[
  { "name": "Иван Иванов", "email": "ivan@mail.ru", "phone": "79991112233" },
  { "name": "Пётр Петров", "email": "petr@mail.ru", "phone": "79992223344" }
]
```

- Каждый покупатель = **1 пара (2 соседних места)**.
- `--pairs N` переопределяет число пар (по умолчанию = число контактов).
- Если контактов меньше, чем пар — контакты циклически повторяются (проверено: один email на несколько заказов работает).

## Что может сломаться и что я уже заложил

- **Афиша/МХТ меняет разметку страницы** → резолвер `resolveEventSessions` ловит отсутствие кнопок и логирует; сессии можно задать жёстко `--session`.
- **Афиша меняет API** → все запросы обёрнуты в `api()` с проверкой `res.ok` и читаемым текстом ошибки; ошибка попадает в письмо/лог.
- **Email не проходит** → `errors` + письмо; покупатель не теряется (повтор до 3 раз).
- **Нет почты в .env** → письмо не уйдёт, но ссылки будут в `data/sniper-results.json` и в админке (монитор предупредит).
